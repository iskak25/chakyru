# Пользователи и Pro

## Роли

- `guest` — зарегистрированный пользователь без подписки.
- `pro` — редактирование всех шаблонов до `proExpiresAt` (UTC).
- `admin` — управление сайтом и доступ ко всем шаблонам.

В админке указаны роль, дата окончания в часовом поясе Бишкека и выбор срока 1/3 месяца. «Применить» назначает выбранную роль. Ручное назначение Pro по умолчанию действует один календарный месяц с момента применения; повторное ручное назначение задаёт новый срок от текущей даты. Оплаченное продление прибавляется к оставшемуся сроку действующего Pro. В конце месяца учитывается число дней следующего месяца.

При истечении срока сервер отказывает в доступе Pro независимо от состояния браузера и cron. Чтение профиля, синхронизация сессии и загрузка админки сохраняют роль `guest` в Firestore. Браузер снимает локальные права по таймеру и обновляет профиль при возвращении на вкладку. Ежедневный cron дополнительно обновляет неактивные аккаунты. Ранее отдельно купленные шаблоны сохраняют собственный доступ; покупка Pro не становится бессрочной покупкой шаблона.

Старые роли `user` преобразуются в `guest`; старые `vip` и бессрочные Pro без даты окончания получают период, рассчитанный от сохранённого `updatedAt`/`createdAt`, либо от времени миграции, если даты отсутствуют. Результат сохраняется один раз. Если период уже закончился, роль сразу становится `guest`. Адреса владельцев из bootstrap-списка остаются администраторами; их нельзя понизить через таблицу.

## Настройка и запуск

1. В серверном окружении сайта задайте `FIREBASE_SERVICE_ACCOUNT`: JSON ключа сервисного аккаунта того же Firebase-проекта, что указан в `NEXT_PUBLIC_FIREBASE_PROJECT_ID`. Не помещайте ключ в `NEXT_PUBLIC_*`, репозиторий или сообщения. У сервисного аккаунта должны быть разрешения читать пользователей Firebase Authentication и читать/писать Firestore.
2. Задайте случайный секрет `CRON_SECRET` в окружении хостинга. `vercel.json` вызывает `/api/cron/expire-pro` ежедневно; обработчик принимает только этот секрет. При другом хостинге настройте такой же защищённый запрос по расписанию.
3. Разверните приложение и обновлённые `firestore.rules`. Правила запрещают пользователю самостоятельно менять срок Pro и платные права.
4. Откройте «Админ → Пользователи → Обновить пользователей». Все страницы Firebase Authentication импортируются в `users/{uid}`. Повторный импорт сохраняет роли, сроки и покупки. Ошибки загрузки показываются как ошибки, а не как пустой список.

Для отдельного импорта из локального окружения с настроенным `.env.local`: `npm run sync:users`. Команда выводит только количество пользователей и распределение ролей.

Проверки без подключения к Firebase: `npm run verify:pro` и `npx tsc --noEmit`. Проверяются импорт с пагинацией, назначение сроков, окончание Pro, снятие роли, продления и повторные уведомления оплаты.

Цена Pro в настройках — за один месяц; три месяца стоят три месячные цены. Срок фиксируется в серверной записи покупки и не берётся из уведомления платёжной системы.
